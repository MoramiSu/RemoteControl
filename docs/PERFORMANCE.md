# 指令响应优化

项目与会话命令由单个串行 worker 处理。桌面连接在成功查询后保留，在错误或退出时关闭；下一条新命令可重新连接。不会自动重放失败命令，也不缓存项目/会话列表来跳过身份核验。

消息持久化后唤醒项目命令 worker；处理完一条后立即检查下一条。新回执持久化后唤醒回复发送器。通知可合并，处理期间到来的通知保留；仍有 1 秒轮询作为兜底。

回复发送器空闲时可立即处理新回执；处理过一个回执/分段后仍至少等待 1 秒，保持原发送节奏。重试继续遵守数据库里的 next_at，不因通知提前重发。普通任务、附件、新建会话和用量查询的工作轮询周期未改变，但它们产生的新回执也会通知发送器。

2026-09-18 隔离实测：原版列表查询通常 700–800 ms，复用连接后连续查询最低 4–8 ms；首次连接仍需约 700–800 ms，且观察到 1602 ms 的桌面查询波动。以上不含飞书网络、发送排队或渲染耗时，不构成端到端响应承诺。

验证：99 项测试通过，包括重复消息、选择身份、错误后不重放、连接复用、通知保留、队列串行排空及发送冷却。实际桌面列表只读验证通过；飞书端到端体验需在部署后使用真实指令确认。
