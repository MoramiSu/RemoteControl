通勤时补一句需求，午休时看一眼进度，出门前没做完的个人项目，随时接着做。切换任务、发送文件、收取结果，都在飞书里完成。回到家，打开电脑，还是**原来的那个会话**。

让家里的电脑继续改代码、整理文档、处理文件，你通过飞书给出下一步要求。执行过程留在家中，进度和结果送到手边。

RemoteControl 将飞书私聊接入已有的 Codex 桌面任务。任务执行仍在你的电脑上，消息和结果通过飞书往返；普通正文原样转发，不经过第二个模型改写。

**无需公网端口、域名或内网穿透，也无需在家中登录飞书客户端。** 本地桥接通过飞书官方 SDK 主动建立长连接。

> **项目状态：实验性 / Windows。** 已实现同会话文字与附件收发。桌面连接依赖特定版本的本地工具和协议，属于非官方集成；Codex 更新后可能需要重新验证兼容性。

## 一段对话，就能继续工作

下面是使用方式示意。编号以机器人实际返回的列表为准：

```text
你 → /rc projects        查看桌面中的项目
你 → /rc project 2       进入列表里的第 2 个项目
你 → /rc tasks           查看该项目的会话
你 → /rc use 1           绑定列表里的第 1 个会话

你 → 接着刚才的方案，把安装步骤简化，再更新 README。
     ↓
     家中 Codex 原会话收到原文，继续执行
     ↓
飞书收到完成结果；符合回传条件的文件也会一并发回

你 → /rc usage           看看还剩多少用量
```

项目和会话通过明确的 `/rc` 指令选择。普通聊天里出现“停止”“切换”等词，不会被误当成控制命令。

## 随身带走的能力

| 能力 | 你可以怎么用 |
| --- | --- |
| **接续原会话** | 在飞书补充需求，回家后在桌面继续同一个任务 |
| **项目与任务切换** | 查看已有项目，在全局或项目内选择、新建会话 |
| **双向文件传输** | 发图片、文档和代码给任务，收取回答中明确链接的输出文件 |
| **适合阅读的回复** | Markdown 卡片、代码块、表格，以及渲染成图片的 Mermaid 图 |
| **随时查询** | 查看当前绑定、执行与队列状态、账户共享用量 |
| **本地接管** | 暂停新消息投递，处理完后再恢复 |
| **少做重复配置** | 双击安装向导、按编号绑定、复用配对、可选登录自启动 |

运行中的新消息会排队。收件、投递和回传分别持久化，遇到不确定的投递结果时保留为待核实，避免盲目重复执行。

## 快速开始

### 准备好这几样

- Windows，交互用户已登录，Codex 桌面已登录并运行，电脑保持唤醒。
- Windows PowerShell。向导会复用兼容 Node.js，或在 Windows x64 上下载经 SHA-256 校验的便携 Node.js 24.19.0 与 npm，无需系统安装。
- 可管理的飞书企业自建应用，启用机器人；电脑能访问飞书和 OpenAI。
- Mermaid 渲染需要本机 Edge 或 Chrome。

已验证桌面版本包括 `26.903.8094.0`、`26.908.4834.0`。兼容性判断以 `scripts/discover-desktop.ps1` 中工具哈希为准。**哈希变化后应重新验证接口，不要仅删除校验。**锁屏场景和长期无人值守尚未完整验收。

### 双击，填凭据，选会话

1. 解压源码包到固定目录，打开并登录 Codex，准备至少两个本机任务，其中一个用于首次遥控测试。
2. 双击根目录 **`Start.cmd`**。首次自动准备 Node.js 和依赖，需要联网访问 nodejs.org 与 npm 仓库。
3. 输入飞书 **App ID / App Secret**。Secret 隐藏输入并由当前 Windows 用户加密保存。
4. 按列表编号选择遥控任务。向导读取本机任务索引，再通过桌面接口核验来源与目标，无需复制 UUID。
5. 选择是否登录 Windows 后自动启动。接收器启动后，将终端的 `/rc pair ...` 命令发给机器人私聊（10 分钟内有效）。
6. 发送一条无害测试要求，确认原桌面任务出现原文、回复回到飞书、本地仍可继续同一会话。

飞书应用创建、权限和发布仍需在平台完成，见 [飞书配置说明](FEISHU_SETUP.md)。若平台要求先建立长连接，可先运行向导到接收器启动，再保存事件订阅。

后续双击同一 `Start.cmd` 会复用配置和配对；已经运行时只显示提示。启用登录启动后无需每天打开此终端，但 Codex 仍须已登录并运行，电脑保持唤醒。关闭前台接收器窗口会停止桥接。

向导核验通过后启用 `desktop-test` 模式（历史名称，表示真实投递）。接口可读不等于完整收发已验收，因此仍需完成第 6 步。旧配置原样保留，包括旧的 `receive-only` 模式；需要启用时使用下方手动命令。

<details>
<summary><strong>手动配置、升级与维护</strong></summary>


- 配置与 DPAPI 加密凭据位于受限的 `.private/`，不要上传或复制给别人。配置不完整时向导停止，不覆盖旧配对。
- 自动下载的运行时及依赖安装标记在 `.runtime/`；不修改系统 PATH，不要求管理员安装 Node。依赖锁文件变化会重新安装，必须先关闭接收器。
- 源码包若被 Windows 标记为来自互联网，`RemoteSigned` 可能拦截脚本。仅在确认来源可信后解除下载 ZIP 的阻止，再重新解压；向导不会修改系统执行策略。
- 无法发现任务时，先打开 Codex 中的已有任务再重试。仅列本机 Codex 任务，兼容性仍受桌面版本校验限制。
- 更换安装目录后重新安装登录启动快捷方式。

手动配置和检查入口仍保留（手动配置需填写真实任务 UUID）：

```powershell
powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\configure.ps1
node .\scripts\check-desktop.mjs
powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\enable-desktop.ps1
powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\start.ps1
# 取消登录启动，不停止当前进程：
powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\install-startup.ps1 -Remove
```

手动开发需要 Node.js `>=24.19.0 <25` 和 npm，运行 `npm ci`、`npm test`。Node 直接运行源码，目前没有构建步骤或完整的 `tsc` 检查。`config.example.json` 使用假 UUID，不能直接用于连接。

## 指令速查

| 指令 | 行为 |
| --- | --- |
| `/rc help` | 帮助 |
| `/rc projects` | 项目列表，0 代表全局 |
| `/rc project 编号` | 选择项目 |
| `/rc project 0` | 退出项目，回到全局 |
| `/rc tasks` | 全局仅列独立会话；项目下仅列项目内会话 |
| `/rc use 编号` | 按最新任务列表核验并切换 |
| `/rc new 名称` | 当前项目中新建会话；全局下新建独立会话 |
| `/rc current` | 当前范围和绑定会话 |
| `/rc status` | 连接、执行及队列状态 |
| `/rc usage` | 账户共享剩余额度及北京时间重置时间 |
| `/rc pause` | 暂停新消息投递，不停止正在运行的任务 |
| `/rc resume` | 恢复投递 |

编号列表有效期 5 分钟，以最近一次列表为准。列表范围受桌面接口限制：全部置顶及最近 50 条中的匹配本机 Codex 任务，**不是完整历史**。较旧会话可先在桌面打开再刷新。

默认是全局模式；已有明确项目选择会在重启后保留。退出项目后须选择或新建独立会话，正文才会继续投递。切换前已持久化的消息保留原目标。`recent`、`project global`、`project none` 已删除。

Git 项目新会话默认使用 worktree，非 Git 项目使用本地目录。若创建只返回临时客户端 ID，桥接提示稍后选取，不盲目重建。项目需要先在 Codex 桌面添加。

## 附件与格式

先发送图片或文件，再发处理要求。传入文件单个最多 20 MiB，最多 20 个待准备附件，数据库中的下载快照总量最多 100 MiB。支持常见图片、Office、PDF、文本、代码、SVG、ZIP；不支持音视频和可执行程序。

文件保存到已核验任务目录的 `.remotecontrol-inbox/<消息哈希>/`，向原会话登记本地路径，**不是桌面原生附件控件**。准备失败会明确通知并暂停后续投递。落盘文件目前不自动清理。

输出附件仅来自相关完成轮次最终回答中的明确本地链接，且需位于任务目录内并符合时间、类型和路径检查。每轮最多 8 个、单个 20 MiB、总量 50 MiB。Mermaid 本地渲染为图片；不支持或失败时保留源码并说明原因。

## 消息如何抵达你的桌面

```text
飞书私聊 → 长连接收件 → 鉴权与 SQLite 持久化
                         ├─ /rc 指令 → 查询或切换 → 回执队列
                         └─ 正文/附件 → 固定目标队列 → DesktopAdapter
                                                      ↓
                                                Codex 原会话
                                                      ↓
飞书结果 ← 格式化/附件发送 ← 持久化回传队列 ← 核验新增轮次和最终回复
```

DesktopAdapter 发现运行中的桌面进程及本地命名管道，验证管道所属进程、工具文件哈希和协议能力，再调用桌面自带工具。不会启动一个独立 Codex CLI 来替代原会话。最终内容还使用任务 ID 核对后的本地记录补全。

## 每一条消息，都有明确状态

- “已收到”表示消息已持久化，不代表已经执行。
- 普通消息只有简短收件回执和最终结果；排队、失败及待处理状态另行通知。
- 发送成功与保存状态之间可能崩溃，因此不宣称恰好执行一次。
- 恢复时，正在投递的消息变成 `delivery_unknown`；核对原任务后再确认，不自动重发。
- 回传内容和发送标识独立持久化，失败限时重试；超过重试窗口需要本地核对。
- 电脑休眠或关机时无法本地收件执行，不承诺离线消息全部补收。

模块职责、数据状态和维护注意事项见 [架构说明](docs/ARCHITECTURE.md)。

## 当前边界

| 能力 | 当前状态 |
| --- | --- |
| 停止正在运行的 Codex 任务 | 暂不支持；`/rc pause` 只暂停新投递 |
| Codex 原生问答卡、权限批准 | 暂不支持远程答复，需要回到桌面处理 |
| 窗口截图 | 暂不支持 |
| 创建或注册项目 | 需要先在 Codex 桌面添加；已有项目中可新建会话 |
| 语音、多用户控制 | 暂不支持；当前面向本人私聊 |
| 锁屏、长期无人值守 | 尚未完整验收 |

仓库内的停止控制器属于未启用实验代码，不代表当前可用功能。

## 凭据和控制权

- **只接受配对的私聊。** 首次配对固定租户、用户和聊天 ID；配对码是临时凭据，不要公开。
- **密钥在本机保存。** App Secret 使用当前 Windows 用户的 DPAPI 加密，配置目录限制访问权限。
- **保留 Codex 的权限机制。** 桥接不会自动批准所有操作；需要桌面介入时仍由用户处理。
- **控制接口留在本机。** 飞书消息通过长连接接收，桌面工具经本地命名管道调用，不对公网开放控制端口。
- **注意传输内容。** 消息与任务结果会经过飞书；本地数据库保存消息和回传记录。仅在你有权使用的项目和数据范围内操作。
- **使用公司飞书时，先确认数据边界。** 企业账号中的消息可能受组织管理，请自行判断私人项目资料是否适合传入。

## 常见问题

| 现象 | 检查项 |
| --- | --- |
| 机器人收不到消息 | 应用发布/可见范围、私聊权限、事件订阅、长连接及是否已配对 |
| 附件下载缺权限 | 消息读取权限与 `im:resource`，以平台返回的缺失权限为准 |
| 桌面连接失败 | Codex 是否运行、工具哈希是否改变，运行 `node scripts/check-desktop.mjs` |
| 只看到少量会话 | 当前全局/项目范围，以及置顶和最近 50 条接口限制 |
| 改配置后未生效 | 配置在启动时加载，需在队列安全时重启接收器 |
| 发送后状态待核实 | 先核对原任务，不要通过删除数据库或重复发送来恢复 |

## 开发与发布

```powershell
npm ci
npm test
powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\export-source.ps1
```

导出脚本按文件白名单生成 `dist/` 下的干净源码目录及 ZIP，可用该目录创建 GitHub 仓库。它不包含依赖、凭据、数据库、验收聊天记录或本机运行历史。

不要上传 `.private/`、`.runtime/`、`runtime/`、`phase0-*` 或本机 `CURRENT.md`。`.gitignore` 无法移除已经提交的文件，发布前仍应检查暂存内容。不要运行历史一次性验收脚本；它们可能发送消息，且不属于发布包。

目前未附开源许可证；公开源码前由维护者决定授权方式。项目不捆绑 Codex 应用代码或其工具服务文件。

欢迎提交可复现的问题和改进。报告连接问题时，请附 Windows / Codex / Node 版本、复现步骤和脱敏后的错误信息；不要附 App Secret、配对码或整个 `.private/` 目录。
